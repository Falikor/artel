# Обновление Артели на минике

Используйте `update_artel.py` из **новой** версии. Нужен Python 3.9+; дополнительные пакеты не нужны. Скрипт работает локально на минике с двумя отдельными папками: распакованной новой версией и существующей установкой. Он не скачивает код и не меняет настройки автозапуска. В обычном режиме процессы запускаются вручную; режим `--managed` автоматически дожидается работы и возвращает прежние процессы (см. ниже).

## Полный пакет обновления и проверка переноса (2.19.1)

Для переноса используйте единый архив: он содержит все модули демонов и сервера,
разделы дашборда, вложенные спрайты и их JSON-описания, шаблоны субагентов и инструкции.
Сборка на компьютере с новой полной версией проекта:

```bash
python3 build_artel_release.py --output output/artel-2.29.0-update.tar.gz
```

В архив не входят рабочие конфиги, память, логи, секреты, настройки офисов или презентации.
Это пакет обновления существующей установки, а не первоначальной настройки новой.
`artel-release.json` содержит список файлов и SHA-256. Если файл потерян или повреждён,
новый updater откажется обновлять установку до остановки процессов.
Используйте updater именно из распакованного пакета: старый скрипт не проверяет манифест.
Теперь также обновляются корневые `README.md`, `UPDATE.md` и сборщик пакета.

Скопируйте архив на миник в `~/Downloads`. Далее выполните **на минике** команды ниже.
`~/Documents/artel` — пример пути действующей установки: замените его своим.
Каждая распаковка создаёт отдельную временную папку, чтобы не смешивать версии:

```bash
ARTEL_RELEASE_DIR="$(mktemp -d "$HOME/artel-release.XXXXXX")"
tar -xzf "$HOME/Downloads/artel-2.29.0-update.tar.gz" -C "$ARTEL_RELEASE_DIR"

python3 "$ARTEL_RELEASE_DIR/artel-new/update_artel.py" \
  --source "$ARTEL_RELEASE_DIR/artel-new" \
  --target "$HOME/Documents/artel" --managed --dry-run

python3 "$ARTEL_RELEASE_DIR/artel-new/update_artel.py" \
  --source "$ARTEL_RELEASE_DIR/artel-new" \
  --target "$HOME/Documents/artel" --managed --wait-timeout 14400

python3 "$ARTEL_RELEASE_DIR/artel-new/update_artel.py" \
  --source "$ARTEL_RELEASE_DIR/artel-new" \
  --target "$HOME/Documents/artel" --verify-only

cd "$HOME/Documents/artel"
python3 artel.py status
```

Команды используйте последовательно в одном терминале; при ошибке остановитесь и прочитайте
сообщение. Для `--managed` уже работающие процессы должны поддерживать протокол 2.11.0+.
Если данные хранятся вне установки, добавьте `--data-path` к команде обновления, как описано ниже.

Перед копированием скрипт показывает абсолютные пути, количество новых, изменённых и
совпадающих файлов, а также состав модулей, интерфейса и ассетов. После копирования он проверяет
содержимое **всех** файлов пакета в целевой установке. Ошибка проверки запускает откат
затронутого кода. `--verify-only` проверяет совпадение без остановки процессов и записи файлов;
несовпадение возвращает ненулевой код выхода. Лишние файлы старой установки не удаляются.
Старый вывод «обновлено — 3» объединял новые и заменённые файлы и не доказывал полноту пакета.

Обычная папка проекта без манифеста по-прежнему поддерживается с явным предупреждением:
её полноту скрипт подтвердить не может. Для переноса используйте архив, созданный выше.

### Если после обновления виден прежний дашборд или спрайты

1. Выполните `--verify-only` из нового пакета с тем же `--target`. Он укажет отсутствующие
   или отличающиеся файлы. Проверьте, что `--target` — папка, из которой запускается дашборд.
2. Откройте работающий дашборд по его HTTP-адресу (обычно `http://127.0.0.1:8765/`),
   затем обновите страницу с очисткой кэша. `output/Artel_Interactive.html` — отдельная
   презентация, а не живой дашборд; обновление кода её не меняет.
3. Проверьте прежнюю команду запуска: `--assets` и переменная `OFFICE_ASSETS` могут указывать
   на внешний старый пак. `--managed` сохраняет эти настройки. Встроенные обновлённые
   спрайты находятся в `<папка установки>/office_dashboard/assets`. Чтобы использовать их,
   смените путь ассетов в настройках запуска и перезапустите дашборд. Внешний пак updater
   не перезаписывает; `--data-path` только включает его в резервную копию.

Установленные определения в `~/.gigacode/agents/` обновляются отдельно по инструкции в конце файла.

## Порядок действий

1. Скопируйте новую версию на миник в отдельную папку, например `~/Downloads/artel-new`. Не заменяйте ею рабочую папку.
2. Посмотрите план (не меняет файлы и не останавливает процессы):

   ```bash
   python3 "$HOME/Downloads/artel-new/update_artel.py" \
     --source "$HOME/Downloads/artel-new" \
     --target "$HOME/Documents/artel" --dry-run
   ```

3. Дождитесь завершения текущих задач. Временно выключите автоперезапуск через launchd или другой менеджер, если он настроен. Остановите демонов и отдельно dashboard привычным способом. Для супервизора Артели:

   ```bash
   cd "$HOME/Documents/artel"
   python3 artel.py stop
   ```

4. Выполните обновление (пути примеров замените своими):

   ```bash
   python3 "$HOME/Downloads/artel-new/update_artel.py" \
     --source "$HOME/Downloads/artel-new" \
     --target "$HOME/Documents/artel"
   ```

5. Только после успешного завершения:

   ```bash
   cd "$HOME/Documents/artel"
   python3 artel.py check
   python3 artel.py start
   python3 artel.py status
   ```

   Если используете launchd, верните прежний автозапуск вместо отдельного `artel.py start`. Dashboard запустите прежней командой с теми же параметрами. Обновите страницу браузера и проверьте имена, офисы, места и статистику.

## Что сохраняется

До первой замены создаётся полная копия рабочей установки в соседнем каталоге `artel-backups/artel-ДАТА-ВРЕМЯ-…/installation`. Внутри резервной копии есть `manifest.json` со списком изменяемых файлов и результатом обновления. Папка отдельной копии доступна только владельцу. Нужен свободный объём для всей установки, включая репозитории, если они лежат внутри неё. При ошибке создания копии код не меняется.

Обновляются корневые скрипты, Python-модули `jira_gigacode` и сервера dashboard, статические файлы интерфейса, ассеты разрешённых типов, документация и два шаблона `config/example.json.sample` и `config/example-services.json.sample`. Лишние файлы не удаляются. **Рабочие конфиги `config/*.json`, `memory/`, `logs/`, `.env`, имена, персонажи, цены, `building.json`, `building.json.rooms.json` и `building.json.buildings.json` не копируются из новой версии и не перезаписываются.** Имена конфигов и идентификаторы демонов остаются прежними.

Если память или настройки расположены вне рабочей папки (через `memory.path`, переменные окружения или параметры dashboard), добавьте каждый внешний файл/каталог в резервную копию:

```bash
python3 "$HOME/Downloads/artel-new/update_artel.py" \
  --source "$HOME/Downloads/artel-new" \
  --target "$HOME/Documents/artel" \
  --data-path "$HOME/artel-data/memory" \
  --data-path "$HOME/artel-data/dashboard"
```

Внешние данные не обновляются и сохраняются в `external/0`, `external/1` и т. д.; соответствие исходным путям записано в manifest. Скрипт не пытается угадать внешние пути из конфигов и окружения. Символические ссылки в полной резервной копии сохраняются ссылками: для копирования содержимого внешнего каталога укажите его через `--data-path`. Символические ссылки в путях обновляемого кода отклоняются.

`--backup-dir /путь` меняет место хранения копий. Оно должно находиться вне источника и установки. Одновременные запуски обновления одной установки блокируются. Проверка работающих процессов — дополнительная защита; автоперезапуск нужно отключить заранее.

## Ошибки и восстановление

При ошибке замены файлов скрипт автоматически возвращает уже затронутые файлы кода из копии и удаляет созданные им новые файлы. Память и состояние при этом не восстанавливаются поверх текущих данных. Ошибка отката выводится явно, исходная копия остаётся доступной.

При выключении питания или принудительном завершении автоматический откат не гарантируется. Не запускайте частично обновлённую установку. Для полного восстановления остановите процессы и автоперезапуск, переименуйте неудачно обновлённую папку, затем скопируйте `installation` из резервной копии на её прежний путь. Внешние данные восстанавливайте отдельно по manifest только при необходимости. Резервные копии скрипт не удаляет.

## Автоматическое ожидание и возврат процессов (2.11.0)

После того как **уже запущенные** демоны, супервизор и dashboard обновлены до 2.11.0, используйте:

```bash
python3 "$HOME/Downloads/artel-new/update_artel.py" \
  --source "$HOME/Downloads/artel-new" \
  --target "$HOME/Documents/artel" \
  --managed --wait-timeout 14400
```

Сначала по-прежнему можно добавить `--dry-run`. Параметры `--data-path` и `--backup-dir` действуют и в автоматическом режиме.

Процесс обновления:

1. Демоны перестают брать новые задачи. Текущая задача заканчивает всю цепочку, включая отчёт и учёт результата. Исследование, ретроспектива или проверка памяти, если уже начались, тоже заканчиваются. Опросы Jira также должны завершиться.
2. Каждый процесс подтверждает безопасную точку. Dashboard закрывает приём запросов, завершает текущие HTTP-обработчики и SSE. Супервизор прекращает запуск новых демонов.
3. После общего подтверждения дочерние демоны завершаются. Сам супервизор, dashboard и демоны, запущенные без супервизора, остаются в минимальном режиме ожидания; они не выполняют работу. Это позволяет сохранить их исходное окружение и связь с launchd без выгрузки секретов в файлы.
4. Создаётся резервная копия, обновляется код. После этого ожидающие процессы заменяют себя новой версией через `exec`, сохраняя интерпретатор, аргументы, окружение и рабочую папку. Супервизор восстанавливает активные конфиги; ранее остановленные не включает.
5. Скрипт ждёт регистрации перезапущенных процессов и возврата дочерних демонов. Это подтверждает запуск, но не заменяет проверку Jira/Jenkins и рабочих задач через `artel.py status` и журнал.

При тайм-ауте **ожидания задач** код не меняется: обслуживание отменяется, текущая задача не прерывается. При ошибке установки с успешным откатом возвращается старый код. Если остановка/откат не подтверждены, автоматическое возобновление блокируется, чтобы не запускать частично обновлённую установку.

Первый переход с 2.10.0 и более старых версий выполняется по обычной инструкции выше. Старые процессы не умеют безопасно подтверждать завершение работы; `--managed` откажется их принудительно останавливать. Настройки launchd менять для штатного `--managed` не требуется: управляющие процессы сохраняют PID и не выходят до `exec`. Не запускайте параллельно другой менеджер обновления или ручной перезапуск.

Служебное состояние обслуживания находится в `.artel-maintenance/` и не включается в резервную копию. Если updater аварийно завершился после начала замены кода, процессы останутся ждать. Проверьте `manifest.json` последней копии, завершите восстановление кода при необходимости и **только после проверки целостности установки** удалите `.artel-maintenance/request.json` — это разрешает ожидающим процессам возобновление. Если есть сомнения, остановите все процессы и выполните полное восстановление по инструкции выше.

### Определения субагентов

`~/.gigacode/agents/` или `.gigacode/agents/` рабочего репозитория не меняется автоматически.
Порядок установки и сохранения прежнего определения описан в [subagents/README.md](subagents/README.md).

## После обновления до 2.29.0

Перезапустите демонов и dashboard, затем обновите страницу. Вкладка **Промпты**
позволяет задавать роль, исполнителя и инструкции семи этапов для каждого демона;
сохранение через UI применяется между задачами без последующего перезапуска.
Настройки находятся в `logs/{instance}-prompts.json` и сохраняются updater.
Выбранный субагент должен быть установлен в GigaCode; профиль «Тестировщик» работает
и со штатным исполнителем. Подробности: [Промпты](docs/PROMPTS.md).

Таблицы статистики и рабочие списки показывают по 20 записей; **Показать ещё** добавляет
следующую порцию. Итоги, графики и CSV продолжают учитывать все записи выбранного периода.

## После обновления до 2.28.0

Перезапустите демонов и dashboard, затем обновите страницу. Обновите установленное
определение субагента по [инструкции](subagents/README.md): добавлен блок конкретного
вопроса перед `CODE_GENERATION_BLOCKED`. Старый отчёт без блока тоже поддерживается.

- `BLOCKED` ожидает уточнения в Jira и не увеличивает счётчик ошибок. Для возврата
  в бэклог используется безопасный прямой переход в один из `explore.statuses`.
- Изменения описания или обсуждения позволяют вернуться к задаче; статусы и собственные
  автоотчёты повтор не запускают. Паузы, исключения и текущая область поиска соблюдаются.
- Ранее исследованные задачи переоцениваются при изменении содержания с прежним
  интервалом минимум 14 дней, заменяя комментарий. Для старых записей без отпечатка
  первое чтение фиксирует исходную версию; последующие изменения отслеживаются.
- Запросы подтверждения повтора и спорные результаты PR публикуются в Jira, если
  включены `jira.enabled` и `jira.result_comments`. Отправки хранятся в постоянной очереди.
- Фавикон следует выбранной теме. README стал быстрым стартом; подробности находятся
  в [Runbook](docs/RUNBOOK.md), [справочнике настроек](docs/CONFIGURATION.md) и [CHANGELOG](CHANGELOG.md).

Обновление сохраняет `logs/*-blocked.json` и `logs/*-notifications.json` вместе
с прежними журналами, памятью, настройками и рассадкой. Полный пакет включает `docs/`.

## После обновления до 2.23.0

В «Команде» офисы показаны этажами пиксельного здания. Нажмите название этажа для входа
или персонажа для открытия его панели. Перетаскивание и кнопка «Переселить» работают между этажами.
При первом чтении каталога офисам добавляется постоянный `building_level` в
`building.json.rooms.json`; прежние офисы, закреплённые места и имена сохраняются.
Новый офис получает следующий свободный номер сверху. Удаление пустого этажа не перенумеровывает остальные.

В шапке можно выбрать светлую, тёмную или системную тему. Выбор сохраняется в браузере,
независимо от конфигов демонов. Перезапустите дашборд и обновите страницу с очисткой кэша.

## После обновления до 2.22.0

Перезапустите дашборд и демонов (при `--managed` это делает updater), затем обновите страницу
с очисткой кэша: **Ctrl+Shift+R** на Windows/Linux или **Cmd+Shift+R** на macOS.
Появится новое меню: «Команда», «Статистика», «Переделки», «Аналитика», «Ретроспективы», «Память».
Логи GigaCode и управление доступны в отдельных вкладках панели выбранного демона.

Форматы рабочих данных не меняются: память, конфиги, история, имена, офисы, рассадка,
персонажи и цены сохраняются по прежним путям. Перенастраивать демонов или подтверждать уроки
заново не нужно. Несохранённые формы браузера завершите или отмените перед обновлением страницы.

## После обновления до 2.21.1

Вход владельца больше не нужен. Откройте демона → «Логи GigaCode»:
технические события доступны сразу, а «Ход работы» показывает краткую хронологию.
Перезапустите дашборд и демонов; в режиме `--managed` это делает скрипт обновления.
Оставшийся от 2.21.0 файл `logs/.dashboard-owner-token` не используется.
Старые запуски не преобразуются в события задним числом.
