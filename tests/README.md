# Тесты демона JIRA → GigaCode

Запуск из корня проекта (рядом с `jira_to_gigacode.py`), нужен только Python 3.9+ и git:

```bash
python3 -m unittest discover -s tests              # все тесты, несколько минут
python3 -m unittest discover -s tests -v           # с названиями тестов
python3 -m unittest discover -s tests -p 'test_git_flow.py'   # один файл
TEST_LOGS=1 python3 -m unittest discover -s tests  # с логом демона и выводом поддельного CLI
```

Сеть, Jira, Jenkins и GigaCode не нужны:

- **git** — настоящий, на временных репозиториях; origin — локальный bare-репозиторий.
  Глобальный git-конфиг разработчика (подпись коммитов, хуки) отключён.
- **GigaCode** — `tests/fake_gigacode.sh`. По тексту команды он понимает, кто его вызвал, и ведёт себя
  по переменной: генерация — `FAKE_MODE` (коммит с маркером, без маркера, только временные файлы,
  коммит в develop, зависание…), ревьюер — `FAKE_REVIEW` (`approve`, `changes`, `none`, по вызовам через
  запятую: `changes,approve`), доработка — `FAKE_REWORK`, исследование — `FAKE_EXPLORE`.
  `FAKE_PROMPT_DIR` сохраняет все команды, которые получил CLI.
- **Jira** — `FakeJira` в `tests/helpers.py` подменяет `jira_client.jira_request`: задача, статусы, переходы, лейблы, комментарии.
- **Jenkins** — подменяется `urlopen` в модуле `jira_gigacode.jenkins`.
- Переменные окружения демона (`JIRA_TOKEN`, `REPO_PATH`…) на время тестов убираются,
  `tmp/.env` не читается.

| Файл | Что проверяет |
|---|---|
| `test_config.py` | приоритет env/конфига, префиксы проекта, `.env`, КЭ и ключ инстанса, переезд логов, флаги CLI |
| `test_prompt_control.py` | отдельные настройки промптов, валидация и конфликты версий, границы задач/фоновых операций, реальный stdin fake CLI, сохранение/сброс и read-only HTTP API |
| `test_tokens.py` | подсчёт токенов: текст, JSON, записи чатов, без двойного счёта |
| `test_branch_config.py` | настраиваемая база, репозиторий только с main, ENV и сервисы, наследование фоновыми проверками, защита основной ветки |
| `test_git_flow.py` | успех генерации (маркер / без маркера), таймаут и восстановление, доставка в remote, временные файлы, коммит в develop, базовая ветка из комментариев |
| `test_jira_and_reports.py` | JQL и фильтры, несуществующие статусы, лейблы и деплой Jenkins, кулдаун, комментарии-отчёты, маскировка секретов |
| `test_startup_and_dry_run.py` | `--check`, `--dry-run` и запуск скрипта целиком как процесса |
| `test_review.py` | вердикты ревью, доработка по замечаниям, блокировка перевода, замечания в следующей попытке, ревьюер не трогает клон |
| `test_experience.py` | уроки агента, файл опыта (дубли, лимит, ручной режим), опыт в следующей команде, заметки по задаче |
| `test_explore.py` | исследование бэклога: комментарий, без повторов, переисследование после изменений, шаблон команды, репозиторий не меняется, Markdown → Jira |
| `test_requirements_snapshot.py` | отпечаток заголовка, описания и обсуждения; изменения людей учитываются, проверенные сообщения Артели и смена статуса не запускают работу повторно |
| `test_blocked.py` | отдельное ожидание BLOCKED, вопрос и прямой переход в бэклог, отсутствие ретраев без уточнения, возобновление обычной задачи и переделки |
| `test_notifications.py` | постоянные уведомления Jira, обновление своего комментария, восстановление после ошибок и неопределённого POST без дублей |
| `test_supervisor.py` | супервизор: запуск по конфигам, перезапуск с паузой, ошибка конфига, ручная остановка, удалённый конфиг, версия и `--outdated` |
| `test_routing.py` | сервис задачи по названию и лейблам, вопрос в задаче (один раз, повтор после изменений), работа в репозитории сервиса, проверки всех репозиториев |
| `test_dashboard_data.py` | цены и стоимость задач, CSV, простой с последней задачи, КЭ, сервис и кэш в истории |
| `test_stop_control.py` | остановка с дашборда: флажок, прерывание GigaCode, кнопки «Остановить»/«Запустить» |
| `test_retro.py` | ретроспектива: слита как есть / после правок людей / squash / открыта / удалена, доработки, комментарии, расписание, уроки и отчёт |
| `test_log_archive.py` | ротация логов и архив по месяцам: copytruncate, логи GigaCode по возрасту и при повторном прогоне, блокировка, без дубля лога в stdout под супервизором |
| `test_quality.py` | исходы задач из ретроспективы (`outcomes.json`) и итоги дашборда: доли, недели, фильтры, повторная сдача |
| `test_tasks_and_proposals.py` | статистика по задачам Jira (ошибки и потом успех — одна задача), стоимость по попыткам, CSV, счётчики карточки, журнал предложений в простое |
| `test_pr_review.py` | Bitbucket REST, пагинация, владение PR, повторные ответы, сбои, проверки исправлений и управление спорными случаями |
| `test_main_loop.py` | проход опроса, повтор только перевода, кулдаун и комментарии, остановка по сигналу, «проверить сейчас» |

`test_updater.py` проверяет перенос новых разделов и вложенных спрайтов, состав архива без
рабочих данных, контрольные суммы, отказ при неполном пакете, `--verify-only` и откат при
ошибке проверки установленных файлов. `test_maintenance_update.py` проверяет ожидание задач
и перезапуск реальных тестовых процессов с сохранением параметров дашборда.

Добавляя сценарий, начинайте с `DaemonTestCase` из `helpers.py`: он даёт чистое окружение,
`self.make_repo()`, `self.config(work)`, `self.run_generation(key, cfg, mode)` и `self.jira`.
Новое поведение поддельного CLI — новая ветка `case` в `fake_gigacode.sh`.

Побочные файлы в корне проекта: `jira-agent.log` и папка `logs/` создаются самим скриптом при
импорте — как при обычном запуске демона.

`test_portable_workspace.py`: межпроцессные блокировки, безопасная проверка PID, Windows Job Object
(только Windows), аналитика с неполными измерениями, чтение/решения по памяти, HTTP-ограничения,
изолированный запуск `up/down`, повторный запуск и занятый порт.
На Windows отдельно: `py -3 -X utf8 -m unittest discover -s tests -p test_portable_workspace.py`.

`test_requirements_rework.py`: очередь ручных переделок, отмена и защита API, смена конфига,
остановленные запросы без автоповтора, недоступная/изменившаяся Jira, сохранение старой ветки,
отдельный учёт и полный прогон с поддельным GigaCode.
`node tests/test_office_social.js`: визиты без изменения рассадки, возврат, прерывание работой
и реакции с учётом уменьшения движения. Node нужен для проверок интерфейса, не для запуска дашборда.

Все проверки JavaScript-интерфейса (Node нужен только для разработки):

```bash
node --test tests/test_*.js tests/test_*.cjs
```

`test_prompt_editor.js`: черновики отдельных демонов и этапов, предпросмотр без сохранения,
возврат к конфигу, конфликты, ошибки и запоздалые ответы сервера, применение настроек через SSE,
защита несохранённого ввода и режим демо.

`test_dashboard_pagination.js`: независимые списки по 20 записей, «Показать ещё» до конца
выборки, сохранение страниц при автообновлении, сброс при фильтрах/сортировке, все записи
журнала без прежнего ограничения в 400 строк, полные итоги и источники памяти.

`test_feature_control.py`: сохранение переключателей, приоритет UI над env и сервисами,
конфликты версий, выключение Jira/Jenkins, границы между задачами, HTTP read-only/Origin,
вывод CLI до перевода строки и выхода процесса, корректная сборка UTF-8, изоляция логов демонов.

`test_dependencies.py`: связанные backend/frontend-задачи, порядок в одном КЭ, разрешение
`backend-ready` на фронтенде другого КЭ, несколько зависимостей, пагинация поиска, отсутствие
ретраев при ожидании, обновление одного комментария, очередь переделок, dry-run и фоновые функции.
Development API подменён; ветка с кодом, пустая и удалённая ветки проверяются настоящим Git
на временном локальном origin. Проверяется выбор репозитория/базы бэкенда и очистка временных refs.

`test_pr_review.py` (2.20.0): TLS без CA как в Jira, включение системных/явных CA, общий анализ всех замечаний PR, включая вложенные, один проверенный коммит/push и отдельные ответы, независимая проверка возражений, частичный сбой POST, восстановление после push и миграция журнала прежнего режима. Bitbucket и GigaCode подменены; Git и тестовые команды выполняются на временных локальных репозиториях.
