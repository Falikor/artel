## Быстрый запуск: Linux, macOS и Windows

После установки Python, Git и GigaCode CLI создайте рабочие `config/*.json` из `.sample`,
задайте пути к репозиториям и секреты в `tmp/.env`. Шаблоны `.sample` сами не запускаются.

**Linux / macOS:**

```bash
python3 artel.py up
# без открытия браузера / с другим портом:
python3 artel.py up --no-browser --port 8766
# остановить супервизор, его демонов и дашборд:
python3 artel.py down
```

**Windows 10/11:** дважды нажмите `start-artel.cmd`. Для остановки — `stop-artel.cmd`.
Файлы запуска сами переходят в каталог установки и включают UTF-8.
Альтернатива в PowerShell из каталога Артели:

```powershell
py -3 -X utf8 artel.py up
py -3 -X utf8 artel.py status
py -3 -X utf8 artel.py down
```

`up` поднимает дашборд на `http://127.0.0.1:8765/`, запускает супервизор со всеми включёнными
конфигами и открывает браузер. Повторный вызов использует уже запущенные процессы.
Если порт занят, команда сообщает ошибку **до запуска демонов**. Для смены порта сначала `down`.
Закрытие окна браузера не останавливает Артель. `down` использует обычную остановку демонов:
текущая работа прерывается с сохранением механизмов восстановления, это не ожидание окончания задач.
Демоны, запущенные отдельно от супервизора, не принадлежат ему и этой командой не останавливаются.

Журнал дашборда: `logs/artel-dashboard.log`, сведения о запуске: `logs/artel-dashboard.json`.
Ручной запуск `office_dashboard/server.py` остаётся доступен; такой дашборд `down` не останавливает.
Автозапуск при входе в ОС отдельно настраивается средствами ОС.

На Windows:

- Git и GigaCode должны быть доступны текущему пользователю через `PATH` либо полный путь.
  Проверьте `git --version`, `gigacode --version` и `py -3 -X utf8 artel.py check`.
- В JSON удобно писать пути как `C:/work/service`; обратные слеши нужно удваивать.
- Команды тестов должны работать на Windows: например `mvnw.cmd`, `gradlew.bat`, `npm.cmd`,
  `python`. Автодетектор учитывает Windows для Maven, Gradle и npm/pnpm/yarn. Для нестандартных сборок задайте `memory.verify_commands`
  и `bitbucket.test_commands` массивами аргументов.
- Блокировки используют Windows byte-range locks; проверка PID не посылает сигнал процессу.
  CLI и тесты запускаются через отдельный Windows Job Object, который завершает оставшиеся
  дочерние процессы при выходе управляющего процесса.
- Логи GigaCode лежат в системной временной папке (`tempfile.gettempdir()`, на Windows обычно `%TEMP%`);
  дашборд и архиватор используют тот же путь.
- `update_artel.py`, включая `--managed`, пока предназначен для Linux/macOS и явно отклоняет
  запуск на Windows. Для Windows остановите Артель, сделайте копию установки и обновляйте только код,
  сохраняя `config/`, `tmp/`, `memory/`, `logs/` и JSON-настройки `office_dashboard/`.

Проверка этой версии выполнена на macOS. Нативный Windows-тест Job Object включён в
`tests/test_portable_workspace.py`, но на macOS пропускается. Запуск с корпоративным GigaCode
на настоящей Windows ещё не проверен; WSL можно использовать с Linux-путями и Linux-версией CLI.

## Запуск через супервизор (рекомендуется)

```bash
python3 artel.py start              # поднять всех демонов из config/*.json в фоне
python3 artel.py status             # кто работает, что делает, сколько раз падал, какая версия
python3 artel.py restart            # перезапустить всех (например после обновления кода)
python3 artel.py restart hrppa      # перезапустить один — по имени конфига
python3 artel.py restart --outdated # только тех, кто работает на старой версии кода
python3 artel.py check              # проверить окружение всех конфигов, ничего не запуская
python3 artel.py memory forget-explore   # убрать из memory/*.md уроки, записанные исследованием бэклога
python3 artel.py archive            # повернуть большие логи и убрать старые в архив сейчас
python3 artel.py stop               # остановить всех
```

```
Супервизор: работает, pid 5909 · версия кода демонов 2.0.0
ДЕМОН   КОНФИГ              PID   СОСТОЯНИЕ       ЭТАП        ЗАДАЧА     ПЕРЕЗАП.  ВЕРСИЯ
Марина  config/paymt.json   5911  работает        ждёт задач  —          0         2.0.0
Олег    config/hrppa.json   5912  работает        пишет код   HRPPA-514  1         2.0.0
Игорь   config/crmx.json    —     ошибка конфига  —           —          3         —
```

Супервизор сам перезапускает упавших демонов (5 → 10 → 20 … секунд, не чаще раза в 5 минут),
подхватывает новые конфиги и останавливает удалённые. Демон, не прошедший проверку окружения,
повторяется раз в 5 минут, а остановленный вручную (`kill`) не перезапускается до `artel restart`.
Вывод каждого демона — в `logs/{конфиг}-stdout.log`, журнал супервизора — `logs/artel-supervisor.log`.
Под супервизором лог демона в `stdout.log` не дублируется: там остаются вывод GigaCode в терминал
и аварийные трейсбеки, а сам лог — в `logs/{КЭ}-agent.log`.

## Логи и архив

Логи не растут бесконечно и не теряются — старое уходит в **`logs/archive/ГГГГ-ММ/`**, сжатое gzip,
и хранится бессрочно (удаляйте месяцы руками, когда не нужны):

- лог демона, его `stdout.log`, журнал супервизора и `jira-agent.log` — когда файл больше
  `logs.max_mb` (20 МБ): содержимое уходит в архив, файл начинается заново (пишущий процесс этого
  не замечает);
- логи GigaCode (`gigacode_<KEY>*.log` в системной временной папке) — старше `logs.cli_keep_days` (14 дней), в
  `logs/archive/ГГГГ-ММ/gigacode/`. Когда задачу запускают заново, прошлый прогон сразу уходит в архив,
  а не затирается новым.

Архиватор запускают супервизор (раз в 10 минут), каждый демон (раз в час) и `python3 artel.py archive`
(сразу; заодно покажет, сколько места занимает архив по месяцам). Одновременно работает только один.
История задач, журнал сдачи и исходы (`*-history.jsonl`, `*-delivered.jsonl`, `*-outcomes.json`) не
архивируются: по ним считается статистика, а растут они на строку за задачу. Смотреть архив:
`zcat logs/archive/2026-10/ci3191860-agent-*.log.gz | less`, искать — `zgrep`.

[Все настройки этого механизма](CONFIGURATION.md).

Супервизор настроек конфига не читает — для него те же значения задаются переменными окружения.

Чтобы Артель поднималась вместе с компьютером, отдайте системе команду `python3 /путь/artel.py run`
(супервизор в текущем процессе): на macOS — `launchd` (plist с `KeepAlive`), на Linux — `systemd`
(`Restart=on-failure`), рабочая папка — папка проекта.

## Запуск одного демона вручную

```bash
python3 jira_to_gigacode.py config/hrppa.json             # в этом терминале
python3 jira_to_gigacode.py config/hrppa.json --check     # только проверить окружение
python3 jira_to_gigacode.py config/hrppa.json --dry-run   # один проход «что бы сделал», без изменений
python3 jira_to_gigacode.py --version
```

**Проверка окружения** выполняется при каждом старте: репозиторий и `origin`, ветка из `general.base_branch`, GigaCode CLI,
токен и проект Jira, джоба и параметры Jenkins, CLI ревьюера, файл опыта, статусы бэклога.
Ошибки останавливают старт, предупреждения — нет.

**Остановка:** `kill <pid>` (SIGTERM) — демон прерывает GigaCode, если тот работает, и завершается за
секунды. Оборванный прогон не будет выдан за готовую работу: при следующем запуске демон отложит его
коммиты в `refs/ai-team-interrupted/…`. Перед новым запуском задачи может потребоваться
явное разрешение в панели **Повторы**; см. [Runbook](RUNBOOK.md).

## Что демон пишет в `logs/`

| Файл | Зачем |
|---|---|
| `{КЭ\|проект}-agent.log` | лог инстанса (`-dryrun.log`, `-check.log` — пробные запуски) |
| `{КЭ\|проект}-state.json` | текущий этап, задача, версия, heartbeat (каждые 10 с) — для дашборда |
| `{КЭ\|проект}-history.jsonl` | по строке на каждую закрытую задачу: итог, время, стенд, токены — для статистики |
| `{КЭ\|проект}-retries.json` | исключения, паузы, допуски и состояние повторных попыток; сохраняется после перезапуска |
| `{КЭ\|проект}-blocked.json` | вопросы исполнителя и отпечатки постановки для ожидания BLOCKED |
| `{КЭ\|проект}-notifications.json` | очередь доставки и ID комментариев о решениях владельца в Jira |
| `{КЭ\|проект}-requirements.json` | отдельная очередь и результаты переделок |
| `{КЭ\|проект}-features.json` | решения переключателей UI и ревизия настроек |
| `{КЭ\|проект}-cli-events.json` | ограниченное окно событий текущего/последнего запуска GigaCode |
| `{КЭ\|проект}-pr-review-*.json` | обработка замечаний PR, подготовленные ответы и неопределённые отправки |
| `{КЭ\|проект}-pending-transitions.json` | задачи, где код запушен, но не удался перевод: повторяется только перевод |
| `{КЭ\|проект}-issue-notes.json` | замечания ревью для следующей попытки по задаче |
| `{КЭ\|проект}-explored.json` | какие задачи бэклога уже изучены |
| `{КЭ\|проект}-proposals.jsonl` | по строке на каждое исследование бэклога: оставлен ли комментарий, время, токены — для статистики |
| `{КЭ\|проект}-delivered.jsonl`, `{КЭ\|проект}-retro.json` | журнал сданных задач и учёт ретроспектив |
| `{КЭ\|проект}-outcomes.json` | исходы сданных задач (слита, правили люди, брошена) — для статистики |
| `archive/ГГГГ-ММ/` | старые логи, gzip (см. «Логи и архив») |
| `{КЭ\|проект}-poke`, `{КЭ\|проект}-stop` | флажки «проверь Jira сейчас» и «остановись» от дашборда; демон сам их удаляет |
| `artel-supervisor.*`, `{конфиг}-stdout.log` | супервизор и вывод демонов под ним |

## Токены GigaCode

После каждого прогона (генерация, ревью, доработка, исследование) демон пытается узнать расход
токенов — по очереди:

1. `general.tokens_regex` из конфига;
2. JSON-статистика в результате CLI (текущий адаптер использует `stream-json`);
3. строки вида `Total tokens: 12 345`, `Input tokens: …`, `Токенов: …` в выводе;
4. записи чата (`--chat-recording` уже включён) в `~/.gigacode`, `~/.qwen`, `~/.gemini`
   (или `general.gigacode_chats_dir`), изменённые за время прогона.

Найденное попадает в лог (`Токены GigaCode: всего …`), историю, отчёт в задаче и статистику. Если в логе
такой строки нет — ваш CLI пишет расход в другом формате: задайте `general.tokens_regex` или
`general.gigacode_chats_dir`. Без этого статистика честно покажет «—».

## Версия демона

Версия кода — `__version__` в `jira_gigacode/__init__.py`. Демон пишет её в `state.json`: дашборд и
`artel status` помечают демонов, которые после обновления кода не перезапущены. Меняйте версию при
каждом выпуске, затем `python3 artel.py restart --outdated`.
