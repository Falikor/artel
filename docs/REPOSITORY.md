# Компактный репозиторий и локальная установка

В Git храните исходный код, тесты, документацию и обезличенные `.sample`-конфиги.
Рабочая установка дополнительно содержит ассеты, секреты, память, журналы и настройки
дашборда. Они остаются на компьютере и исключены из Git через [`.gitignore`](../.gitignore).

## Что входит в исходники

| Файлы | Назначение |
|---|---|
| `jira_gigacode/`, `daemon_state.py`, точки запуска | Демоны, интеграции, супервизор и управление процессами |
| `office_dashboard/artel_dashboard/`, `office_dashboard/static/` | Сервер и веб-интерфейс |
| `config/*.sample`, `subagents/` | Шаблоны конфигурации и инструкция исполнителя |
| `tests/` | Регрессионные проверки, fake CLI и изолированное UI-демо |
| `docs/`, README, UPDATE, CHANGELOG | Инструкции пользователя и разработчика |
| `build_artel_release.py`, `update_artel.py` | Перенос кода на действующую установку с сохранением данных |

Тесты, демонстрационный сервер и скрипт сборки нужны разработчикам, даже если основной
процесс их не импортирует. Статические файлы интерфейса подключаются HTML-страницей;
PNG и JSON ассетов выбираются через манифесты и обход каталогов. Отсутствие имени файла
в Python-импортах не означает, что файл не используется.

## Что остаётся только локально

| Каталог или файлы | Почему не включены в Git |
|---|---|
| `output/`, `.presentation-build/` | Архивы выпусков, презентации, рендеры и скриншоты; не нужны для запуска |
| `config/*.json`, `config.json`, `tmp/`, `.env*` | Настройки установки и секреты; образцы `.sample` остаются в Git |
| `memory/`, `logs/`, `*.log*` | Память, текущие задания, история, повторы и решения пользователя |
| `office_dashboard/*.json*` | Имена, внешность, рассадка, офисы, корпуса и цены |
| `office_dashboard/assets/` | Исходные сторонние ассеты с отдельными условиями распространения |
| `__pycache__/`, `.DS_Store`, виртуальные окружения | Восстанавливаемые локальные файлы |

Не удаляйте память, конфиги или JSON-настройки ради уменьшения размера: `.gitignore`
исключает их из будущего коммита без изменения работающей установки. Для проверки
нового репозитория после `git init` используйте:

```bash
git status --short --untracked-files=all
git check-ignore config/team.json tmp/.env office_dashboard/building.json
git add --dry-run .
```

Перед коммитом просмотрите его состав. `.gitignore` не убирает файлы из уже существующей
истории Git и не защищает файлы, добавленные с `git add -f`. Для данных по произвольным
внешним путям правила требуется задать отдельно. Настройки `.gitattributes` сохраняют
переносимые окончания строк скриптов, включая `.cmd` для Windows.

## Ассеты и запуск после клонирования

[Лицензия имеющегося пака](../office_dashboard/assets/LICENSE_EN.txt) разрешает
использование в продукте, но ограничивает распространение исходных ассетов и их
извлечение. Поэтому в публичный репозиторий не включены ни PNG, ни JSON этого пака.
Отдельного разрешения на публичное распространение дополнений AI Artel в проекте нет;
они также оставлены локально. Текст лицензии сохранён.

Для полной офисной сцены установите свой разрешённый к использованию пак в
`office_dashboard/assets/`, сохранив его структуру. Альтернатива — внешний каталог:

```bash
OFFICE_ASSETS=/path/to/office-assets python3 artel.py up
```

В PowerShell:

```powershell
$env:OFFICE_ASSETS = 'C:/artel-assets'
py -3 -X utf8 artel.py up
```

Для отдельного дашборда есть параметр `--assets`; структура пака описана в
[архитектуре дашборда](../office_dashboard/README.md#ассеты-assets-41-мб).
Без подходящего пака анимированная офисная сцена недоступна. Код, настройки и память
не требуют хранения исходных ассетов в Git.

## Архивы обновления и презентации

`build_artel_release.py` собирает локальный пакет кода **вместе с имеющимися ассетами**
для вашей установки на минике. Это не архив публичного GitHub-репозитория. Не загружайте
его в публичные Releases вместе с лицензированными исходными ассетами.

Презентации и старые выпуски можно хранить рядом с проектом в отдельном архивном каталоге.
Они не участвуют в запуске веб-сервиса. Перенос не заменяет резервную копию рабочих данных:
для обновлений продолжайте использовать [штатный updater](../UPDATE.md).
