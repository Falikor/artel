## Опыт по репозиторию (`memory/`)

Память разделена на три слоя. Успешный прогон, AI-ревью или повторение одной мысли
**не подтверждают** правильность урока.

- **Постоянные правила** — `<memory.path>.rules.md`. Их ведёт владелец; демон не меняет этот файл.
  Они первыми попадают в контекст. Если правила превышают `max_chars`, построение команды
  останавливается с ошибкой: важные правила не обрезаются молча.
- **Подтверждённый опыт** — записи в `<memory.path>.store.json` с основанием подтверждения,
  областью применения и датой проверки. Только они, вместе с правилами, идут в следующую задачу.
- **Кандидаты** — новые наблюдения генерации, ревью, доработки и ретроспективы.
  Агент может выдать **ноль уроков**; общие советы и детали одной задачи запрашивать запрещено.
  Кандидаты не включаются в рабочий контекст. `explore.learn`, если включён, тоже создаёт только кандидаты.

Старый `memory/{КЭ|проект}.md` сохраняется без изменений. При первом обращении его пункты
импортируются как кандидаты, а не как проверенные правила. Самые старые сверх лимита уходят
в историю; полный исходный текст остаётся в старом Markdown. Закреплённые правила нужно
явно перенести в `.rules.md`. Автоматического доверия прежним записям нет.

Внутри бюджета выбираются целые записи: сначала правила, затем подтверждённые знания,
подходящие по области (подстрока текста задачи) и совпадающим словам. Без области запись
относится ко всему репозиторию. Это простой текстовый отбор, не семантический поиск.
Точные повторы объединяются со счётчиком наблюдений; регистр и операторы сохраняются.
Похожие формулировки показываются при разборе, но автоматически не склеиваются:
«делать X» и «не делать X» могут быть очень похожи.

[Все настройки этого механизма](CONFIGURATION.md).

Обслуживание выполняется при чтении/записи памяти и командой `sweep`. Через 90 дней
подтверждённая запись снова становится кандидатом на пересмотр и исчезает из контекста.
Повторение агентом не продлевает срок подтверждения. Кандидаты старше 30 дней и записи сверх
лимитов уходят в ограниченный журнал `.history.jsonl` / `.history.jsonl.1`. История старше
этой ротации не хранится; исходный старый Markdown не удаляется. Блокировка файла и атомарная
запись защищают хранилище при одновременной работе демонов и ручном разборе.

**Автоматическая проверка кандидатов включена по умолчанию.** В простое, после исследования,
демон проверяет одного кандидата, не чаще раза в час для каждой памяти. Для нескольких сервисов
используются их собственные репозитории и настройки `memory`. Работа идёт в отдельной Git worktree
от свежей ветки `memory.verify_base` (по умолчанию `origin/<general.base_branch>`); основная рабочая копия не используется для тестов.

1. Отдельный вызов GigaCode исследует кандидат, постоянные правила и подтверждённый опыт,
   находит точные цитаты кода и выбирает тесты из доступного списка.
2. Демон сам проверяет цитаты по конкретному коммиту Git и запускает тесты, а не доверяет
   рассказу агента о запуске. Изменение файлов/HEAD проверяющим блокирует подтверждение.
3. Второй вызов GigaCode оценивает, доказывают ли реальные результаты весь вывод. Только
   непосредственно наблюдаемый структурный факт допускается без запуска тестов; утверждения
   о поведении и работоспособности команд требуют успешных релевантных тестов.
4. Подтверждённая запись автоматически попадает в рабочую память с коммитом, цитатами,
   результатами команд и обоснованием. Противоречие, неясный вывод, отсутствие подходящих
   тестов или падение тестов дают `disputed` — для владельца. Сбой CLI/сети или таймаут
   оставляет кандидата на автоматический повтор через 24 часа.

Это проверка с участием модели, не формальное доказательство: смысл и релевантность тестов
оценивает GigaCode, и он может ошибаться. Можно выбрать другую модель через `verify_extra_args`.
Worktree изолирует файлы, **не системные права и сеть**. Тесты проекта исполняются с правами
демона; команды из текста кандидата напрямую не запускаются. Демон не запускает отдельную установку зависимостей или деплой; сами сборщики могут
скачивать зависимости при выполнении тестов. Тестовые команды запускаются с `CI=true`.

[Все настройки этого механизма](CONFIGURATION.md).

Автовыбор тестов для Python: при наличии `tests/` используется `python -B -m unittest discover -s tests`,
а при `pytest.ini`, корневом `conftest.py` или секции pytest в `pyproject.toml` — `python -B -m pytest -q`.
Также распознаются Maven (`mvn test` / `./mvnw test`), Gradle (`gradle test` / `./gradlew test`), npm/pnpm/yarn (`test`
из package.json), Go (`go test ./...`) и Rust (`cargo test`). Для монорепозитория или
нестандартного запуска задайте команды явно, например:
`"verify_commands": [["npm", "test", "--", "--run"], ["npm", "run", "typecheck"]`.
Аргументы должны соответствовать конкретному проекту. Пустой список отключает запуск тестов,
но позволяет проверять структурные факты. Неподтверждённые кандидаты не участвуют в обычных задачах.
Через 90 дней автоматическое подтверждение истекает и запись снова проходит проверку.
Спорные кандидаты повторно проверяются только после команды `retry`; срок хранения кандидатов
по-прежнему ограничен `candidate_days`.

Разбор памяти (вместо `memory/t.md` укажите базовый путь нужного демона):

```bash
python3 artel.py memory list memory/t.md --disputed --config config/t.json
python3 artel.py memory retry memory/t.md ID --config config/t.json
python3 artel.py memory approve memory/t.md ID --evidence "Проверил make test на коммите abc123" --config config/t.json
python3 artel.py memory approve memory/t.md NEW_ID --evidence "Проверил новый Makefile" --replaces OLD_ID --scope backend --config config/t.json
python3 artel.py memory reject memory/t.md ID --config config/t.json
python3 artel.py memory sweep memory/t.md --config config/t.json
```

`ID` берётся из `list`. `--scope` можно повторять; без него знание общее для репозитория.
`--replaces` позволяет объединить или заменить устаревший вывод, сохранив событие в истории.
Ручное подтверждение через `approve` выполняет владелец: эта команда не запускает тесты
и не проверяет истинность введённого текста. После истечения срока запись можно подтвердить
заново, пока она ещё находится среди кандидатов. Без `--config` применяются стандартные
лимиты и переменные окружения; для нестандартных настроек передавайте конфиг демона.
Постоянные правила автоматически не проверяются на устаревание — их пересматривает владелец.

## Ретроспектива: демон учится на своих задачах

Раз в несколько дней (`retro.every_days`, по умолчанию 7), в ночное окно (`retro.window`,
по умолчанию `01:00-05:00` по времени компьютера) и только в простое демон разбирает, что стало
с задачами, которые он сдал не меньше `min_age_days` (2) дней назад:

- **слита ли работа и как:** целиком; со сжатием (squash) или вручную — по коммиту с ключом задачи
  в базе; ещё открыта; ветку удалили без слияния;
- **правили ли люди его код:** коммиты поверх его работы до слияния и diff «как сдал → как стало»;
- **доработки после слияния:** коммиты в базе с ключом задачи;
- **что в Jira:** текущий статус и комментарии людей после сдачи.

Эти факты демон собирает сам, только git и Jira. Потом один прогон GigaCode на репозиторий разбирает
их: что люди исправляли и почему, какие ошибки повторяются, что делать иначе. Уроки сохраняются
в `.store.json` с источником «ретроспектива» как кандидаты: действия людей служат материалом
для разбора, а выводы агента проходят отдельную проверку. Полный разбор — в `memory/retro/{КЭ}[-сервис]-ГГГГ-ММ-ДД.md`. Ещё не слитые задачи ждут
следующей ретроспективы, но не дольше `max_age_days` (30) — потом разбираются как есть.

Для ретроспективы демон ведёт журнал сданных задач `logs/{КЭ}-delivered.jsonl` (ветка и коммит на
момент сдачи). Задачи, сданные до версии 2.2.0, в журнале отсутствуют — разбираться будут новые.
Исход каждой проверенной задачи ретроспектива записывает в `logs/{КЭ}-outcomes.json` — из него
дашборд строит раздел «Что стало со сданными задачами» во вкладке «Статистика».

```bash
python3 jira_to_gigacode.py config/hrppa.json --retro --dry-run   # какие факты собрал бы — без агента
python3 jira_to_gigacode.py config/hrppa.json --retro             # ретроспектива сейчас, не дожидаясь ночи
```
