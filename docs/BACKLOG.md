# Исследование бэклога

## Исследование бэклога в простое

Когда задач на реализацию нет, демон ищет бэклог **в своём Jira-проекте, по КЭ и статусам** — без фильтров по эпику и
исполнителю, сначала недавно изменённые:

```
project=<jira.project> AND cf[<jira.ci_field>] = "<КЭ>" AND status IN ("TO DO", "Backlog") ORDER BY updated DESC
```

Без КЭ (`jira.ci_field` + `general.ci_id`) — `project=<jira.project> AND status IN (…)`, о чём
предупредит проверка окружения. Выдача листается страницами по 50, пока не найдётся неизученная
задача (не дальше `explore.max_scan`). Для неё демон запускает GigaCode с `/opsx:explore` во временной
копии репозитория (ничего не меняется). Итог — вопросы к требованиям,
затронутый код, подходы и риски, критерии приёмки, оценка сложности — появляется комментарием в задаче.
Повторное исследование запускается, если изменились заголовок, описание или обсуждение людей
после предыдущего исследования. Учитываются добавление, изменение и удаление комментария.
Смена статуса, лейблов и собственные отчёты Артели не считаются новой постановкой.
Повторное предложение появляется не чаще раза в 14 дней; больший настроенный интервал сохраняется.
Интервал действует отдельно для каждой задачи и сохраняется после перезапуска демона.
При повторном исследовании демон редактирует свой предыдущий комментарий вместо создания нового.
Автор сверяется с текущим аккаунтом Jira, а принадлежность демону — с меткой инстанса
(для старых комментариев — с заголовком и именем демона). Если дубли уже есть, обновляется последний;
старые комментарии не удаляются. При ошибке чтения или редактирования новый дубль не создаётся.
Аккаунту Jira нужно право редактировать собственные комментарии.

Демон получает обсуждение через REST и передаёт его исследователю вместе с актуальной постановкой.
Отпечаток содержимого и ID собственного комментария сохраняются в `logs/{инстанс}-explored.json`.
Если журнал старой версии не содержит отпечатка или был утрачен, демон один раз запоминает
текущую постановку без повторной публикации: достоверно восстановить прежний текст нельзя.
Следующие изменения отслеживаются обычным способом. Сохраняйте `logs/` при переносе.

[Все настройки этого механизма](CONFIGURATION.md).

Например, свой суб-агент вместо OpenSpec:
`"prompt_template": "вызови суб агента /explorer изучи задачу {key}: {summary}\n{description}\nИтог выведи между EXPLORE_START и EXPLORE_END"`.
