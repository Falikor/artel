# Артель демонов — как устроен дашборд

**Русский** · [English](README.en.md)

Запуск и описание возможностей — в [руководстве дашборда](../docs/DASHBOARD.md); быстрый старт — в [README](../README.md). Здесь — устройство для тех, кто будет
его дорабатывать.

## Архитектура

```
демон ──► logs/{id}-state.json  (атомарно, heartbeat 10 с)  ┐
      ──► logs/{id}-history.jsonl (строка на задачу)         │
      ──► logs/{id}-delivered.jsonl, -outcomes.json          ├─► server.py ──SSE──► static/js/ (сцена, панель)
      ──► logs/{id}-agent.log                                ┘          ├─ /api/history ─► js/stats/stats.js
                                                                        └─ /api/quality ─► js/stats/quality.js
дашборд ──► logs/{id}-poke (двойной клик) ──► демон опрашивает Jira сразу
        ──► logs/{id}-stop («Остановить»)  ──► демон прерывает GigaCode и выходит
        ──► logs/artel-restart-{конфиг} («Запустить») ──► супервизор поднимает демона
```

- `server.py` — точка входа (флаги — `python3 server.py --help`); сам сервер — пакет `artel_dashboard/`, только stdlib:

  | Модуль | Что внутри |
  |---|---|
  | `common.py` | пути по умолчанию, `tail_lines`, `pid_alive`, атомарная запись JSON |
  | `assets.py` | поиск ассетов: персонажи (06), двери (07), лаунж (08), мебель, Кокошка |
  | `daemons.py` | `read_all`: state.json, разбор лога старых версий, последняя задача, имена и персонажи |
  | `stores.py` | `Names`, `Characters`, `Prices` — то, что правится из интерфейса |
  | `history.py` | запуски → задачи Jira (`group_tasks`: итог по последней попытке, траты — сумма), предложения в простое, стоимость, CSV |
  | `quality.py` | исходы сданных задач по данным ретроспективы: доли, недели, демоны и сервисы |
  | `handler.py` | HTTP: API, SSE, кнопки управления; `make_server` — хранилища живут на сервере, не в глобальных |
  | `app.py` | флаги, демо, запуск |

- `static/js/` — интерфейс без сборки и библиотек: обычные `<script>` с общей глобальной областью,
  **порядок подключения в `index.html` важен** (сначала константы и классы, потом те, кто их использует):

  | Файл | Что внутри |
  |---|---|
  | `office/scene-map.js` | этапы демона (`STAGE`), карта и граф путей, места, реплики |
  | `core/util.js` | `$`, `esc`, время сервера, загрузка картинок, поиск пути |
  | `office/sprites.js`, `office/worker.js` | спрайты и персонаж-демон: ходьба, этапы работы |
  | `office/idle-life.js`, `office/lounge.js`, `office/cat.js` | жизнь в простое, тумба с PlayStation, Кокошка |
  | `office/render.js` | кадр: двери, предметы, цикл анимации, подписи |
  | `core/data.js` | загрузка ассетов, поток SSE, применение снимка состояния |
  | `panel/cards.js`, `panel/drawer.js` | карточки демонов, панель с логами, клики по сцене |
  | `panel/characters.js`, `panel/controls.js` | выбор персонажа, «Остановить»/«Запустить», имена |
  | `stats/quality.js`, `stats/proposals.js`, `stats/stats.js` | раздел качества, предложения в простое и сама вкладка «Статистика» (SVG без библиотек) |
  | `main.js` | старт — последний скрипт |

  Этапы `reviewing`/`rework` персонаж проводит за столом, `exploring` — у доски. На карточке — версия
  кода демона (`daemon_version`), устаревшие помечены ⚠.
- `demo.py` — симуляция демонов через тот же `daemon_state.py`, с историей за две недели и исходами сданных задач за 12 недель
  (с ревью, доработкой, исследованием бэклога и одним «устаревшим» демоном).

### API

| Метод | Путь | Что |
|---|---|---|
| GET | `/api/assets` | ассеты: фон, персонажи (06), набор 08, двери (07), тумба, предметы кухни, кошка (с `--cat`) |
| GET | `/api/state`, `/api/stream` | состояние всех демонов (SSE раз в секунду при изменениях) |
| GET | `/api/history?days=N`, `/api/history.csv` | задачи Jira за период (`records`, попытки — в `runs`) и предложения в простое (`proposals`); CSV — строка на задачу |
| GET | `/api/quality?days=N&id=` | исходы сданных задач: итоги, недели, демоны/сервисы |
| GET/POST | `/api/prices`, `/api/characters` | цены токенов; выбор персонажа (`{"id", "character"}`, пустой — сброс) |
| GET | `/api/log?id=`, `/api/gigacode?issue=` | хвост лога демона / лога GigaCode |
| GET/POST | `/api/names` | имена демонов (`{"id": "hrppa", "name": "Олег"}`) |
| POST | `/api/poke` | «проверь Jira сейчас»: `{"ok": true}` или `{"reason": "busy" \| "old" \| "offline"}` |
| POST | `/api/stop` | остановить демона: флажок `{id}-stop` (демон 2.0.2+) или SIGTERM старому демону на этом компьютере |
| POST | `/api/start` | запустить остановленного: запрос супервизору `artel-restart-{конфиг}`; без супервизора — `no_supervisor` |

## Сцена

Координаты — пиксели фона 1254×1254, позиция персонажа — точка ног. `?debug=1` рисует граф проходов
и точки. Всё настраивается в начале `static/js/office/scene-map.js`:

- `N`, `EDGES` — граф проходов (Дейкстра); `SEATS` — рабочие места, `LOUNGE` — диван, кресло и места стоя;
- `MEET`, `BOARD`, `PRINTER`, `CHAT_SPOTS`, `COOLER`, `KITCHEN`, `WINDOWS` — точки этапов и отдыха;
- `SOLO`, `DIALOGS`, `VISIT_DIALOGS`, `LINES` — реплики; `ACTIVITY_WEIGHTS` — частота занятий;
- `CAT_*` — Кокошка: масштаб по строкам атласа, места прогулок, лежанки, фразы.

### Анимации персонажей

- **06_CHARACTER_ANIMATIONS** (кадр 128×128, ноги 64,112, масштаб ×1.125): ходьба в 4 стороны, работа, стулья.
  Ходьба вбок собирается из 4 фаз (шаг → ноги вместе → шаг → ноги вместе): в атласе ноги во всех кадрах
  расставлены одинаково. У `worker_orange_yellow` `lounge_left` заменён зеркалом `lounge_right` (`ANIM_FIXES`).
- **08_LOUNGE_AND_SOCIAL** (кадр 160×160, ноги 80,136): диван и кресло — свои клипы
  `{sofa|armchair}_{sit|idle|drink|talk|laugh|game|game_win|stand}_{left|right}`; посадка и вставание
  плавно смещают корень между точкой подхода и местом сидения. Жесты `pat_shoulder/pat_received`,
  `give_item/receive_item`, клипы приставки. Учитываются `flipX` и `frameOverrides`.
- Клип выбирается по типу мебели (`seatedClip`), атлас и точка ног — свои у каждой анимации.

### Двери (07_DOOR_ANIMATIONS)

Фон `character_free_all_doors_open.png` с открытыми проёмами; поверх — створки кабинета, переговорки
и входа (8 кадров, 800 мс) и неподвижные косяки над проходящим. Дверь открывается, когда путь
персонажа или Кокошки пересекает её линию; шаг через линию запрещён, пока она не открыта полностью;
закрывается через 1,1 с.

### Тумба и PlayStation (08)

Одна приставка (`drawer` → `carried` → `installed` → `carried` → `drawer`), состояния тумбы по
`props/media_cabinet/manifest.json`. Смена владельца — по событиям кадров `console_pickup`,
`console_install`, `console_pickup_installed`, `console_store`. Игра начинается, только когда оба
игрока сели, а приставка у ТВ. Если кого-то прервали, сессия завершается, а приставку уберёт следующий
свободный демон (занятие `tidy`).

## Здание и постоянные места (2.8.0)

Общий вид показывает все офисы, занятость и ошибки/потерю heartbeat. Клик по офису открывает
анимированную сцену, клик по жителю — его офис и лог. В сцене показываются только её жители,
а предупреждения из остальных офисов остаются в верхней строке. Статистика остаётся общей.

Группа определяется постоянными полями: `project` и `general.office_group` (если задан), иначе
`general.service`. Без них группировка только по проекту. Например:
`"general": {"office_group": "Платежи"}`. Для демона, который переключается между несколькими
сервисами, это позволяет выбрать постоянный отдел; текущий `detail.service` его не переселяет.
Новые поля передаются в state после перезапуска демона версии 2.8.0.

Каждые 10 закреплённых мест образуют отдельный офис. Назначения сохраняются в `building.json`
рядом с файлом `--characters`; они общие для всех браузеров. Отсутствующий демон сохраняет
место, новые занимают следующие свободные. Поэтому офис может быть заполнен не полностью:
пустая клетка может быть зарезервирована за отсутствующим демоном. Изменение проекта или
явного отдела переносит демона в новую группу. При резервном режиме чтения только логов
проект определяется по имени лога, пока не появится state с настоящим проектом.

Существуют 7 базовых моделей и 6 палитр одежды — 42 сочетания. Автоматическая выдача базовых
моделей балансируется, ранее выбранные модели не меняются. Палитра назначается один раз;
в панели персонажа её можно поменять. Ручной выбор одной модели для многих демонов может
повторять сочетания после шестого жителя — принудительно переодевать владельца система не будет.
Замена палитры применяется к кадрам ходьбы, работы и лаунжа; это варианты существующих моделей,
а не новые рисунки персонажей. Кеш ограничен 256 кадрами; исходные атласы не дублируются.

Вкладка здания и статистика не запускают анимацию скрытого офиса. При смене офиса очищаются
персонажи, очереди социальных действий, состояние приставки и резервы мест. Для общей доски,
принтера и переговорки используются уникальные позиции; остальные жители работают со своего
места вместо наложения персонажей в одной точке.

### Ручное размещение и статистика (2.9.0)

Откройте демона и выберите офис в панели над логом, затем нажмите **Переселить**. Можно создать офис с собственным названием или вернуть автоматическое размещение по проекту/сервису. Ручной выбор сохраняется в `building.json` и имеет приоритет над конфигурацией. Переселение освобождает прежнее место; места отсутствующих демонов остаются зарезервированы. В заполненную комнату переселение отклоняется с объяснением.

Кнопка **Статистика офиса** открывает отчёт по выбранной комнате. На вкладке статистики есть фильтры офиса, демона и периода. Показатели, графики, предложения, итоги ретроспективы и CSV задач учитывают выбранный офис; CSV также учитывает выбранного демона. При переселении история демона учитывается в новом офисе: это отчёт по текущему составу, а не архив размещений. Общая статистика доступна через **Все офисы**.

В интерфейсе используется системный шрифт с поддержкой кириллицы, без загрузки Google Fonts; увеличена контрастность второстепенного текста. Пиксельные ассеты остаются прежними.
### Управление комнатами (2.10.0)

В общем виде здания доступны **Переименовать** и **Удалить пустой офис**. Название меняется без смены идентификатора и мест жителей. После переселения последнего демона комната остаётся доступной для заселения или удаления. Закреплённые места отсутствующих демонов тоже считаются занятыми.

Перетащите карточку демона на другой офис: целевая комната подсветится. Сервер проверяет вместимость и сохраняет постоянное место. При ошибке демон остаётся в прежнем офисе, объяснение появляется над комнатами. Выбор через панель демона также доступен.

Каталог комнат сохраняется рядом с рассадкой в `building.json.rooms.json`. При обновлении существующие офисы добавляются автоматически. Для переноса dashboard сохраняйте `building.json`, `building.json.rooms.json` и, если корпуса переименованы, `building.json.buildings.json`.

### Навигация по карте (2.27.0)

Колесо мыши приближает карту к указателю, перетаскивание перемещает её. На сенсорном
экране двигайте карту одним пальцем, меняйте масштаб двумя. За пределами самой сцены
сохраняется обычная прокрутка страницы. Под картой доступны **− / +**, текущий масштаб
(50–800% относительно автоматического вида), **Весь квартал** и пауза анимации.
На сфокусированной карте: **+ / −** — масштаб, стрелки — перемещение, **Home** — общий вид.
Подписи корпусов остаются читаемыми, этажи выбираются с учётом приближения.
Выбор корпуса или офиса подбирает масштаб заново; новые статусы демонов его не сбрасывают.
Камера хранится только на время открытой страницы и не меняет рассадку или настройки сервера.

### Названия корпусов (2.26.0)

Нажмите **Названия корпусов** над картой, выберите корпус и введите имя до 60 символов.
**Сохранить** обновляет подписи на карте, навигацию и адреса офисов. **Отмена** или Escape
закрывают форму без записи. Названия доступны всем вкладкам dashboard и хранятся
в `building.json.buildings.json` рядом с рассадкой, независимо от браузера. Обновление
сохраняет этот файл; при ручном переносе копируйте его вместе с остальными файлами рассадки.
Номера корпусов, этажи и места демонов от переименования не меняются.


В версии 2.16 добавлены экраны «Аналитика», «Ретроспектива» и «Память».
API: `GET /api/insights`, `GET /api/retrospective`, `GET/POST /api/memory`;
фильтры `office`, `id`, для статистики `days` (0 — всё время).
Серверные модули: `insights.py` (агрегации) и `knowledge.py` (память из конфигов).
Интерфейс: `static/js/stats/workspace.js`. Общий запуск: `python3 artel.py up`.
